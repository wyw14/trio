Guest mode now drives the callback chain through a single convergence point, so each scheduled guest tick runs exactly once on the host thread and in order. A tick or event delivery that reaches the guest after the run has finished now raises `trio.RunFinishedError` explicitly instead of being silently dropped or invoking ``done_callback`` a second time. If the host's ``run_sync_soon_threadsafe``/``run_sync_soon_not_threadsafe`` callback refuses to schedule the next guest tick (e.g. the host loop is closing), the run is torn down cleanly and the failure is delivered to ``done_callback`` as a `trio.TrioInternalError` rather than leaving a dead callback chain and a stuck wakeup state.
